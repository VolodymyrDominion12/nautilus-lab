# 02. Встановлення, налаштування, швидкий старт

## 1. Що потрібно встановити

| Компонент | Версія | Навіщо |
|-----------|--------|--------|
| Python | **3.12 або новіше** | Сам проєкт. У репозиторії вже є `.venv` з Python 3.13. |
| [uv](https://docs.astral.sh/uv/) | будь-яка свіжа | Менеджер залежностей і запуск команд. |
| Git | будь-яка | Контроль версій. |
| Інтернет | — | Лише для `lab ingest` (завантаження історії з Binance). Бектести працюють офлайн. |

Інсталяція з нуля:

```bash
cd nautilus-lab
cp .env.example .env          # локальні налаштування (цей файл не потрапляє в git)
uv sync --extra dev           # базові залежності + тести, ruff, mypy
```

Опційні extras (можна додати пізніше):

| Extra | Що додає | Навіщо |
|-------|----------|--------|
| `dev` | pytest, ruff, mypy, pandas-stubs, pytest-cov | Тести й перевірка якості |
| `ml` | LightGBM | `LightGBMDirectionClassifier` — ML-класифікатор напрямку за ознаками книги |
| `research` | `arch`, `optuna`, `polars` | EGARCH-прогноз волатильності, байєсівська оптимізація параметрів (`--optuna`), Polars-мікроструктура |
| `visualization` | `plotly`, `kaleido`, `simplejson` | HTML-тиршит (`--tearsheet`) |
| `alerts` | `httpx` | Сповіщення в Telegram/Webhook (`--notify`) |

```bash
uv sync --extra dev                                     # мінімум для роботи й тестів
uv sync --extra dev --extra ml --extra research          # + ML, Optuna, Polars, arch
uv sync --extra dev --extra research --extra visualization --extra alerts   # повний стек
```

> **Якщо `uv` не має доступу до свого кеша** (наприклад, у обмеженому середовищі),
> команди можна запускати напряму з віртуального середовища проєкту:
> `.venv/bin/lab research --synthetic` замість `uv run lab research --synthetic`.
> Далі в документації використовується коротка форма `uv run lab ...`.

## 2. Швидкий старт за п'ять команд

```bash
# 1. Перевірити, що все на місці: детерміновані синтетичні дані, мережа не потрібна
uv run lab research --synthetic --bars 3000

# 2. Завантажити реальну історію з Binance (публічні дані, без API-ключів)
uv run lab ingest --start 2025-01-01 --symbols ETHUSDT,BTCUSDT

# 3. Головний крок: walk-forward на реальних даних
#    (0.7 історії — підбір параметрів, 0.3 — звіт, 10 барів розриву)
uv run lab research

# 4. Той самий прогін для простої EMA-стратегії — щоб було з чим порівняти
uv run lab research --robot ema

# 5. Подивитися, які ордери зробив би робот (жоден не піде на біржу)
uv run lab paper --bars 500
```

Жодна з цих команд не надсилає ордерів на біржу. `uv run lab live` — завжди помилка.

## 3. Усі змінні налаштування

Налаштування читаються класом `Settings` (`src/nautilus_lab/infrastructure/settings.py`)
з трьох джерел у такому порядку пріоритету:

1. **змінні середовища оболонки** (найвищий пріоритет — перекривають усе),
2. **файл `.env`** у корені проєкту,
3. **значення за замовчуванням** у коді (найнижчий).

Назви змінних — це імена полів у верхньому регістрі (наприклад, `risk_per_trade` → `RISK_PER_TRADE`).

### Режим і каталог

| Змінна | За замовчуванням | Що робить |
|--------|------------------|-----------|
| `TRADING_MODE` | `research` | `research` / `paper` / `live`. `live` заборонено на рівні коду. |
| `LIVE_ENABLED` | `false` | Запобіжник-прапорець. Навіть `true` не вмикає живу торгівлю — адаптера виконання не існує. |
| `CATALOG_PATH` | `catalog` | Тека Parquet-каталогу з історією. |
| `BAR_INTERVAL` | `1h` | Таймфрейм: `1m`, `5m`, `15m`, `1h`, `4h`, `1d`. |
| `INSTRUMENT_ID` | `ETH/USDT.SIM` | Основний інструмент дослідження. |
| `BAR_TYPE` | `ETH/USDT.SIM-1-MINUTE-LAST-EXTERNAL` | Формат бару для синтетичного режиму. **Фактично не використовується:** синтетика завжди бере 1-хвилинний тип, а каталог будує `bar_type` з `INSTRUMENT_ID` + `BAR_INTERVAL`. Змінна лишена для сумісності. |
| `BINANCE_SYMBOL` | `ETHUSDT` | Символ за замовчуванням для `lab ingest` без `--symbols`. |
| `BINANCE_SYMBOLS` | `["ETHUSDT","BTCUSDT"]` | Список символів для масового `ingest` (JSON-масив). |

### Капітал і ризик

| Змінна | За замовчуванням | Що робить |
|--------|------------------|-----------|
| `STARTING_EQUITY` | `100000` | Стартовий баланс симуляції (у USDT). |
| `RISK_PER_TRADE` | `0.005` | Частка капіталу, яку можна **втратити** в одній угоді (0.5%). Це не «розмір позиції» — розмір вирахується зі стопу. |
| `STOP_PCT` | `0.01` | Стоп 1% ціни — використовується, коли ATR ще не прогрівся. |
| `MAX_DAILY_LOSS` | `0.02` | Денний збиток 2% → нові входи заборонені (circuit breaker). |
| `MAX_DRAWDOWN` | `0.06` | Просадка 6% від піку → нові входи заборонені. |
| `MAX_OPEN_POSITIONS` | `1` | Максимум одночасно відкритих позицій. |
| `KELLY_FRACTION` | `0.25` | Частка від повного критерію Келлі (фракційний Келлі = обмежувач зверху). |
| `MAX_VAR_99` | `0.05` | Порог історичного VaR 99% — вище нього нові входи блокуються. |

### Комісії

| Змінна | За замовчуванням | Що робить |
|--------|------------------|-----------|
| `MAKER_FEE` | `0.001` (0.1%) | Комісія мейкера. Підставляється в інструмент симуляції. |
| `TAKER_FEE` | `0.001` (0.1%) | Комісія тейкера — саме її платять роботи (вони ставлять ринкові ордери). |

Приклад «як у MFT-документі» для ф'ючерсів USDⓈ-M VIP0: `MAKER_FEE=0.0002`, `TAKER_FEE=0.0005`.
Приклад для споту VIP0: `0.001` / `0.001`.

### Робот `regime`

| Змінна | За замовчуванням | Що робить |
|--------|------------------|-----------|
| `ROBOT` | `regime` | Активний робот: `regime`, `ema`, `pairs`, `funding`, `ml_obi`, `glft`, `tri_scan` (див. застереження в [05](05-roboty.md)). |
| `ER_PERIOD` | `20` | Вікно коефіцієнта ефективності Кауфмана. |
| `TREND_EMA_PERIOD` | `40` | Період EMA для вимірювання нахилу (тренду). |
| `SLOPE_LOOKBACK` | `10` | За скільки барів міряти нахил EMA. |
| `ENTER_TREND_ER` | `0.30` | ER вище цього = вважаємо ринок трендовим (вхід у тренд). |
| `EXIT_TREND_ER` | `0.20` | ER нижче цього = тренд закінчився (вихід із тренду). Гістерезис між 0.30 і 0.20. |
| `DONCHIAN_PERIOD` | `20` | Довжина каналу пробою. |
| `BB_PERIOD` | `20` | Період смуг Боллінджера для флету. |
| `BB_K` | `2` | Ширина смуг у стандартних відхиленнях. |

### Робот `ema`

| Змінна | За замовчуванням | Що робить |
|--------|------------------|-----------|
| `FAST_EMA` | `10` | Швидка ковзна. |
| `SLOW_EMA` | `20` | Повільна ковзна. Має бути більшою за швидку. |

### Валідація й VPIN

| Змінна | За замовчуванням | Що робить |
|--------|------------------|-----------|
| `EMBARGO_BARS` | `10` | Розрив у барах між in-sample і out-of-sample. |
| `USE_BAR_VPIN` | `false` | Увімкнути VPIN-фільтр режиму для робота `regime`. |
| `VPIN_BUCKET_VOLUME` | `1000` | Обсяг одного «кошика» VPIN (у базовій валюті). |
| `VPIN_TOXIC_THRESHOLD` | `0.7` | Поріг токсичності потоку: VPIN ≥ 0.7 → токсично. |

### Ключі біржі

| Змінна | За замовчуванням | Що робить |
|--------|------------------|-----------|
| `EXCHANGE_API_KEY` | порожньо | **Не використовується.** Живий адаптер не підключений; ніщо в коді ці ключі не читає. |
| `EXCHANGE_API_SECRET` | порожньо | Те саме. |

### Сповіщення (необов'язково)

| Змінна | За замовчуванням | Що робить |
|--------|------------------|-----------|
| `TELEGRAM_BOT_TOKEN` | порожньо | Токен бота Telegram для сповіщень (разом із `TELEGRAM_CHAT_ID`) |
| `TELEGRAM_CHAT_ID` | порожньо | ID чату, куди надсилати повідомлення |
| `ALERT_WEBHOOK_URL` | порожньо | URL вебхука (Slack/Discord/свій ендпоінт) |

Сповіщення надсилаються лише з прапорцем `--notify` і лише після завершення прогону.
Якщо змінні не задані — використовується «порожній» нотифікатор, який нічого не робить.
Потрібен extra `alerts` (пакет `httpx`).

> **Безпека.** Ніколи не тримайте в `.env` реальні ключі, якщо не плануєте писати живий адаптер
> найближчим часом. `.env` уже в `.gitignore`, але ключі з нього варто видалити (а якщо вони
> колись були справжні — перевипустити на біржі). Проєкт для research-режиму не потребує жодних ключів.

## 4. Перевірка, що все працює

```bash
uv run pytest                       # 149 тестів, включно з локальним рушієм (без мережі)
uv run ruff check --fix && uv run ruff format   # стиль і форматування
uv run mypy src tests               # сувора типізація (strict = true)
```

Очікуваний результат `pytest`: усі тести проходять; є кілька попереджень `Pandas4Warning`
від самого Nautilus — це нормально й не впливає на результат.

## 5. Структура робочої теки

```
nautilus-lab/
├── README.md                         короткий вступ
├── Стратегії MFT Криптоторгівлі 2026.md   вихідний дослідницький документ (джерело ідей)
├── docs/                             <- ця документація
├── .env                              ваші локальні налаштування (не в git)
├── .env.example                      шаблон налаштувань з коментарями
├── pyproject.toml                    залежності, налаштування ruff/mypy/pytest
├── catalog/                          Parquet-каталог завантаженої історії (не в git)
│   └── data/
│       ├── bar/<INSTRUMENT>-<TF>-LAST-EXTERNAL/*.parquet   свічки
│       └── currency_pair/<INSTRUMENT>/*.parquet            описи інструментів
├── src/nautilus_lab/
│   ├── domain/                       чиста логіка (без мережі, без Nautilus)
│   ├── application/                  сценарії використання, ризик, walk-forward
│   ├── infrastructure/               біржа, каталог, рушій бектесту, синтетика
│   └── interfaces/                   CLI `lab` і збірка залежностей
└── tests/
    ├── unit/                         швидкі тести чистої логіки
    └── integration/                  прогон реального рушія Nautilus на локальних даних
```

Детальний опис кожного модуля — у [12-karta-fayliv.md](12-karta-fayliv.md).
