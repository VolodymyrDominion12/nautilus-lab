# research/ — офлайн-контур дослідження

Тут живе все, що робить модель **поза** торговим циклом: промпти, запропоновані
гіпотези та журнал рішень. Ніщо з цієї теки не виконується під час бектесту чи
торгівлі. Деталі й обґрунтування — [docs/14-llm-model-u-torhivli.md](../docs/14-llm-model-u-torhivli.md).

```
research/
├── README.md            ← цей файл
├── prompts/             ← шаблони промптів (01 запускається скриптом, 02–03 — вручну)
├── hypotheses/          ← артефакти: одна модель-відповідь = один JSON-файл
└── journal.md           ← журнал рішень: прийнято / відкинуто і чому
```

## Два контури

| | Гарячий шлях | Офлайн-контур (ця тека) |
|---|---|---|
| Що | Nautilus, `on_bar`, ризик, ордери | промпти, модель, рев'ю, журнал |
| Час | мілісекунди | хвилини |
| LLM-виклик | **ніколи** | норма |
| Артефакт | `Signal` | файл у git → рев'ю людини → код у `domain/` |

Якщо LLM-виклик виконується під час прогону бектесту — це баг, навіть якщо
результат гарний.

## Цикл

```
промпт (prompts/01)  →  модель  →  hypotheses/*.json  →  рев'ю людини
                                                              │
                        journal.md  ←  рішення  ←──────────────┘
                              │
                    domain/<robot>.py + tests  →  purged CV  →  walk-forward OOS
```

## Команди

Файл `prompts/01-generate-alphas.md` — це **чистий промпт**, який іде в модель.
Скрипт підставляє в нього три плейсхолдери: перелік 12 ознак, кількість гіпотез
і дату відсічення. Якщо хоч одного плейсхолдера в шаблоні немає — скрипт падає,
а не шле напів-промпт у модель.

```bash
# Подивитись, який промпт піде в модель (мережі не торкається, ключ не потрібен)
.venv/bin/python scripts/propose_alphas.py --dry-run

# Спитати модель і записати артефакт (потрібен LLM_API_KEY у .env)
.venv/bin/python scripts/propose_alphas.py --count 5 --as-of 2026-09-15

# Інша модель або локальний сервер відкритих ваг (безпека даних)
.venv/bin/python scripts/propose_alphas.py \
    --base-url http://127.0.0.1:11434/v1 --model qwen2.5:14b
```

Коди виходу: `0` — успіх, `2` — конфіг або непридатний артефакт, `3` — збій ендпоінта.
Без `LLM_API_KEY` скрипт **падає закрито** і нічого не вигадує замість моделі.

## Що робити з артефактом

1. Прочитати `hypotheses/*.json` — там `hypotheses[]` і блок `review` зі `status: pending`.
2. Відкинути все, у чого немає економічного механізму або є `unknown_identifiers`
   (вигадана фіча — типова помилка моделі).
3. Реалізувати прийняте в `domain/` за [docs/07](../docs/07-yak-stvoryty-strategiyu.md).
4. Прогнати ворота: `pytest` → `ruff` → `mypy src tests` → purged K-fold →
   `lab research --robot <robot> --folds N` (це і є OOS).
5. Записати рядок у [journal.md](journal.md): що перевірили, яке число, рішення, причина.

## Чого не робити

- **Не показувати моделі OOS-результат і не просити «покращити».** Так OOS стає
  частиною підбору (docs/07, §1).
- **Не питати про конкретні історичні події.** Модель навчена на даних до свого
  cutoff і пам'ятає, чим закінчилась історія, на якій ти збираєшся її перевіряти.
  Це найнебезпечніша пастка цього контуру (docs/14, §6.1).
- **Не запускати згенерований код із реальними ключами.** `lab live` fail closed —
  і це не можна «тимчасово обійти».
- **Не вірити переконливому поясненню.** Артефакт — це гіпотеза, а не результат.
