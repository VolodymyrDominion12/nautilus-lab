# 0002. Одна згенерована таблиця стану

- Статус: прийнято
- Дата: 2026-09-25

## Контекст

Стан кожного робота (статус spec, чи підключений до бектесту, чи є paper, що показав
вимір) повторювався вручну в `docs/21` §1.1.1, §2, §8, `docs/22` §2, §3, §5.1, §7, §8.3 і
`docs/README.md`. Кожна звірка оновлювала 5–7 таблиць, і вони розходились.

## Рішення

`docs/STATUS.md` генерує `scripts/gen_status.py` з того, де поведінка справді живе:
специфікацій (`specs/`), `BACKTEST_WIRED_ROBOTS`, `TICK_VPIN_ROBOTS`, `HAWKES_ROBOTS`,
`PAPER_SUPPORTED_ROBOTS`, `LIVE_PAPER_ROBOTS` і `GateCriteria`.
`tests/unit/test_status_doc.py` падає, якщо файл застарів або якщо spec і код кажуть
різне (наприклад, spec заявляє адаптер бектесту, якого в коді немає).

## Наслідки

Змінив код або spec — виконай `uv run python scripts/gen_status.py` і закоміть
`docs/STATUS.md` у тому ж PR. Інші документи посилаються на таблицю, а не переписують її;
історичні таблиці в `docs/21`/`docs/22` лишаються як історія, з позначкою, що актуальний
стан — у `STATUS.md`.
