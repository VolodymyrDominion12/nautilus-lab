# 0005. Стан фонових джобів у SQLite з усиновленням після рестарту

- Статус: прийнято
- Дата: 2026-09-25

## Контекст

Процеси research/ingest/ML/paper жили в глобальних змінних `api/app.py`. Після
рестарту API (деплой, збій, `--reload`) дашборд показував «idle», хоча ingest ще писав
каталог, і можна було запустити другий поверх першого.

## Рішення

`JobManager` (`api/jobs.py`) тримає слоти й процеси; `JobStore` (`api/job_store.py`)
записує кожен старт і завершення в `data/jobs.sqlite`. При старті API живу дитину
попереднього процесу усиновлюють лише тоді, коли збігаються і pid, і командний рядок з
`/proc`; інакше запуск позначається `lost`. Сироти ніколи не вбиваються.

## Наслідки

SQLite, а не JSON: пишуть кілька потоків, а напівзаписаний файл після kill втратив би саме
той запис, заради якого все зроблено. Код виходу усиновленого процесу невідомий (-1).
Переживає рестарт здебільшого ingest (пише у файл); джоби з виводом у канал зазвичай
гинуть разом з API і чесно показуються як `lost`.
