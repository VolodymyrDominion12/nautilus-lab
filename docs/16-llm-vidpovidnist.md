# 16. Відповідність «LLM у криптотрейдингу.md» і коду

Що з огляду «Великі мовні моделі (LLM) у криптовалютному трейдингу» вже є в nautilus-lab,
що частково, чого немає і чому. Джерело: [LLM у криптотрейдингу.md](../LLM%20у%20криптотрейдингу.md).
Третя мапа тієї самої серії: [08](08-mft-2026-vidpovidnist.md) — MFT-документ,
[13](13-ai-2026-vidpovidnist.md) — ШІ-огляд 2026. Документ [14](14-llm-model-u-torhivli.md)
відповідає на інше питання — *які ролі* LLM корисні. Числа зі статті не переказуються як
факти: вони зібрані в §12.

Легенда:

| Позначка | Значення |
|----------|----------|
| ✅ | Реалізовано **і підключено** (працює через CLI, бектест або скрипт із репо) |
| 🟡 | Реалізовано як **блок** або opt-in шар: викликати можна, у ворота за замовчуванням не входить |
| 🔴 | Не реалізовано / поза скоупом лабораторії |
| ⚪ | Поза кодом (зовнішні бенчмарки, ончейн, інфраструктура) |

## 0. Позиціонування

Стаття описує індустріальний стек: багатоагентні системи, FinGPT і LoRA-донавчання,
факторний майнінг через DSL, мета-еволюцію промптів, ончейн-графи, контамінацію
переднавчання, контрфактичну верифікацію. **nautilus-lab** — research-пісочниця на
годинних барах: п'ять роботів з адаптером (`regime`, `ema`, `pairs`, `vpin_momentum`,
`formulaic_lgbm` — `domain/regime.py::BACKTEST_WIRED_ROBOTS`), `lab live` fail closed.

Збіг із джерелом один і вузький: обидва документи кажуть, що цінність LLM не в прогнозі
ціни, а у швидкості циклу «гіпотеза → код → ворота → висновок». Саме ця частина в репо
реалізована ([14 §9](14-llm-model-u-torhivli.md), [research/README.md](../research/README.md)).
Усе про агентів, що *торгують*, відсутнє — і це рішення, а не прогалина: у гарячий шлях
LLM не викликається. Три речі, що відповідають джерелу буквально: **DSL замість вільного
Python** (`domain/factor_dsl.py`), **регуляризація складності й crowding факторів**
(`recipe_complexity()`, `crowding_hits()`) і **детермінований динамічний стоп, який модель
не може переписати** (`domain/ratchet_stop.py`, opt-in `USE_RATCHET=true`).

## 1. Агенти, MAS, дебати (QRAFTI, FactorMAD, AlphaLogics, Lumibot)

| Що в документі | Стан у коді |
|----------------|-------------|
| Crypto Agent + News Agent + Trading Agent, signal fusion | 🔴 жодного агента в репо немає |
| QRAFTI: ролі аналітика, ризик-менеджера, кодера | 🟡 частковий відповідник — людина + один виклик моделі (`research/prompts/01-generate-alphas.md`), далі ручний код у `domain/` |
| FactorMAD: дебати агентів навколо факторів | 🔴 |
| AlphaLogics: бібліотека ринкової логіки | 🔴 |
| Lumibot: команда «бик / ведмідь / трейдер» | ⚪ зовнішня платформа |
| FS-ReasoningAgent: фактична й суб'єктивна гілки, агент рефлексії | 🔴 немає джерела суб'єктивних даних (новин, соцмереж) |
| Адаптація до режиму (bull/bear) | 🟡 замінник без LLM: `RegimeRouter` (`MarketRegime`) і VPIN-фільтр — адаптація логіки, не ваг текстового сигналу |
| «Сильніші моделі торгують гірше» | ⚪ властивість зовнішніх моделей; прогону LLM-стратегії в репо немає |

Дебати кількох агентів додають вартість і недетермінізм, не додаючи перевірки: суперечка
двох LLM не є тестом. Порівняння «ієрархічна конфігурація проти монолітної» відтворити нічим.

## 3. Гіпотези й факторний майнінг через DSL

| Що в документі | Стан у коді |
|----------------|-------------|
| Обмежена DSL замість вільного коду | ✅ `domain/factor_dsl.py::parse_recipe()` — AST, fail closed на невідомих токенах і функціях |
| Заборона крос-секційних операцій | ✅ `CROSS_SECTIONAL = {"rank", "corr"}` відхиляються: лаб оцінює один інструмент |
| Часові трансформації | ✅ `delay`, `delta`, `ts_mean`, `ts_std`, `ts_min`, `ts_max`, `zscore` |
| Нелінійні перетворення | ✅ `log`, `sqrt`, `abs`, `sign`, `clip`, `pow` |
| «Не надто глибокий» рецепт для ручної інспекції | ✅ `MAX_DEPTH = 6`, `MAX_COMPLEXITY = 32`, відмова від рецепта з однієї сирої колонки (`_is_too_shallow`) |
| Point-in-time без підгляду | ✅ `evaluate_recipe(node, rows, index)` читає лише `rows <= index`; вікна — тільки назад |
| Оцінка рецепта: IC, hit rate | ✅ `application/evaluate_recipe.py::score_recipe()` + `scripts/evaluate_recipe.py` |
| Рецепт як *робот*, що торгує | 🔴 рецепт оцінюється офлайн; `formulaic_lgbm` працює на фіксованих 12 ознаках `FEATURE_NAMES`, а не на довільній формулі |

DSL готовий, IC рахується, але **шляху від рецепта до бектесту немає**: рецепт отримує IC,
а не OOS-число з комісіями. Конвеєр джерела обривається на півдорозі — найдешевша наступна ланка.

## 4. Складність і скупчення факторів (QuantaAlpha)

| Що в документі | Стан у коді |
|----------------|-------------|
| Складність = довжина + вільні параметри + унікальні сирі ознаки | ✅ `recipe_complexity()` = `node_count() + free_param_count() + len(unique_features())` |
| Поріг складності | ✅ `MAX_COMPLEXITY = Decimal("32")` — жорсткою помилкою, не попередженням |
| Структурна схожість через AST | ✅ `ast_similarity()` — найбільше спільне ізоморфне піддерево / максимум розмірів |
| Відхилення кандидата вище порогу схожості | 🟡 `crowding_hits(..., max_similarity=0.85)` працює, **але жоден виклик із репо не передає пул**: `scripts/evaluate_recipe.py` кличе `score_recipe()` без `pool`, тому `crowding_index` на практиці завжди порожній |
| Обов'язковий економічний механізм | ✅ `mechanism` і `kill_condition` — обов'язкові поля `domain/hypothesis.py::_REQUIRED_FIELDS` |

Механізм crowding у коді є, **застосування — ручне**.

## 5. Еволюція промптів і семантична мутація (AlgoEvolve)

| Що в документі | Стан у коді |
|----------------|-------------|
| Внутрішній цикл: LLM покращує стратегію за звітом продуктивності | 🔴 |
| Зовнішній цикл: мета-еволюція самих промптів | 🔴 |
| Автоматичний відбір гіпотез за метрикою | 🔴 |
| Версіонування промпту | ✅ `propose_alphas.py::prompt_sha256()` → поле `prompt_sha256` в артефакті |
| Історія прогонів не перезаписується | ✅ `write_artifact()` додає суфікс `-r2`, `-r3` |

Обидва цикли джерела замкнені на метрику. Тут метрика, побачена моделлю, перестає бути
out-of-sample ([07 §1](07-yak-stvoryty-strategiyu.md), [14 §6.4](14-llm-model-u-torhivli.md)),
тому замикання циклу заборонене архітектурно, а не забуте.

## 7. «Міраж прибутку»: контамінація, витік, контрфактика

| Що в документі | Стан у коді |
|----------------|-------------|
| Temporal knowledge leakage (модель пам'ятає кінець історії) | 🟡 частковий захист: дата відсічення `{{AS_OF}}` у шаблоні + вимога в `SYSTEM_PROMPT` («must not use anything that became known after the stated as-of date») |
| Вимірювання витоку (Shapley-DCLR) | 🔴 |
| TimeSPEC: відбраковування невалідованих тверджень | 🔴 |
| FactFin: контрфактичний симулятор цін | 🟡 `domain/counterfactual.py::perturb_bars()` + `counterfactual_ic` у `score_recipe()` (збурення детерміноване, `magnitude=0.02`) |
| MCTS/UCB для пошуку стратегій | 🔴 |
| RAG: новини як числові вектори, щоб модель не впізнала подію | 🔴 |
| Динамічний бенчмарк CryptoBench / FinLake-Bench | ⚪ |
| Витік у **власному** коді | ✅ `bars.py::validate_bar()`, `windows.py::RollingWindow.prior()`, purged K-fold з embargo (`train_classifier.py::purged_k_fold()`), walk-forward (`domain/walk_forward.py`), PBO/CSCV (`domain/overfitting.py`, `--pbo`) |

Закритий витік **у своєму коді** — те, що взагалі піддається перевірці. Витік **у вагах
чужої моделі** тут не вимірюється нічим: потрібен або контрфактичний контур (є заготовка), або період пізніше тренування моделі.

## 8. Промпти, валідація та виконання

| Що в документі | Стан у коді |
|----------------|-------------|
| `system_prompt` як конституція з межами ризику | 🟡 `propose_alphas.py::SYSTEM_PROMPT` задає **формат** (лише JSON, без торгових рекомендацій, без знання після `as-of`); ліміти ризику описує код, а не промпт |
| Строго валідований JSON на виході | ✅ `extract_json_block()` (знімає фенси й прозу) → `domain/hypothesis.py::parse_hypotheses()` — fail closed |
| Обов'язкові поля гіпотези | ✅ `_REQUIRED_FIELDS`; горизонт ≤ `MAX_HORIZON_BARS = 240`; знак нормалізується з `+1/-1`, `long/short`, `up/down` |
| Pydantic як шар валідації даних для LLM | 🔴 Pydantic є лише для конфігу: `infrastructure/settings.py::Settings` |
| Tool Calling / JSON Schema на рівні API | 🔴 клієнт надсилає лише `messages`, `temperature`, `stream` |
| Вигадані ознаки не проходять непоміченими | ✅ `unknown_identifiers()` не блокує артефакт, а позначає (`count_flagged`); рішення ухвалює людина |
| TA Filter → LLM → детермінований Dynamic Stop-Loss (Pathia) | ✅ opt-in: `domain/ratchet_stop.py` двома фазами — захист від втрат (`initial_ratchet(..., atr_distance=...)` бере `min(percent, ATR)`) і фіксація прибутку з рівнями `(0.08 → 0.04)`, `(0.15 → 0.08)`, поріг `arm_pct=0.0125` |
| «Модель не має права чіпати ризик» | ✅ структурно: `ratchet_stop.py` не залежить від LLM, а `SignalRobot.on_bar` кличе `_apply_ratchet()` **до** сигналу робота |
| Неперервний цикл «API → індикатори → промпт → ордер» (DeepTrade) | 🔴 LLM не викликається з циклу — свідомо |

Ризик тут забезпечує код (`application/risk.py::evaluate_entry()`,
`domain/risk.py::RiskLimits`, `domain/kill_switch.py`), промпт відповідає лише за формат.

## 9. Безпека: ін'єкції, джейлбрейки, ізоляція

| Що в документі | Стан у коді |
|----------------|-------------|
| Непряма ін'єкція промптів через новини/веб | 🔴 захисту немає — і немає джерела атаки: жоден код не тягне зовнішній текст у модель |
| Adversarial news як драйвер збитків | ⚪ поза скоупом (немає новинного фіду й немає торгівлі) |
| Джейлбрейк і «надмірні повноваження» агента | 🟡 структурний імунітет: єдиний вхід у модель — шаблон із репо, єдиний вихід — JSON-артефакт |
| Ізоляція збору даних від виконання ордерів | ✅ за побудовою: `domain/ports.py::ChatCompleter` документований як **offline research only**, жодна стратегія його не імпортує |
| Обмеження привілеїв, whitelists пар | 🔴 ключів виконання немає взагалі: `lab live` → `require_simulated_mode(TradingMode.LIVE)` → `LiveTradingDisabledError` |
| Детерміновані risk gates, які модель не обійде | ✅ `evaluate_entry()` блокує вхід за денним лімітом, просадкою, VaR/CVaR і кількістю позицій |

Найслабше місце — не ін'єкція, а **відсутність тесту на правило**: ніщо не заважає колись
імпортувати `llm_client` у домен. Правило сформульовано в [14 §1](14-llm-model-u-torhivli.md), автоматичної перевірки немає.

## 11. Як увімкнути нові можливості

Офлайн-цикл гіпотез — основна команда `lab propose` (без ключа мережі не торкається; код
виходу `1`, коли `LLM_API_KEY` не заданий). Скрипт `scripts/propose_alphas.py` робить те
саме автономно, з кодами виходу `0`/`2`/`3`:

```bash
uv run lab propose --dry-run                                    # ключ не потрібен
uv run lab propose --count 5 --as-of 2026-09-15 --journal       # артефакт + рядок у журналі
uv run lab propose --base-url http://127.0.0.1:11434/v1 --model qwen2.5:14b
.venv/bin/python scripts/propose_alphas.py --dry-run            # той самий промпт без CLI
```

Оцінити рецепт DSL на реальних барах — друкуються `complexity`, `depth`, `n`, `ic`,
`hit_rate`, `counterfactual_ic`; різниця між `ic` і `counterfactual_ic` і є перевірка «чи не
запам'ятав рецепт конкретний шлях»:

```bash
uv run python scripts/evaluate_recipe.py "trend_er * momentum_10" \
    --catalog catalog --instrument ETH/USDT.SIM --interval 1h --horizon 5 --sign 1
```

Динамічний стоп замість звичайного (сигнали робота не змінюються):

```dotenv
USE_RATCHET=false      # як раніше: тільки percent/ATR-стоп
USE_RATCHET=true       # дві фази: захист від втрат + фіксація прибутку
RATCHET_ARM_PCT=0.0125 # рух у плюс, після якого стоп починає «храповик»
```

Ворота перед тим, як вірити гіпотезі з артефакту:

```bash
uv run python -m pytest tests/unit/test_hypothesis.py tests/unit/test_propose_alphas.py \
    tests/unit/test_llm_client.py tests/unit/test_factor_research.py -q
uv run python scripts/train_formulaic_lgbm.py --catalog catalog --output models/formulaic.txt
uv run lab research --robot formulaic_lgbm --folds 4
uv run lab research --robot regime --folds 4 --journal   # планка buy&hold + рядок у журналі
uv run lab research --robot regime --pbo --pbo-blocks 8
```

`--pbo` закриває дірку «сітка мала, отже безпечно», про яку джерело попереджає в розділі
про перенавчання. Застереження: `--robot formulaic_lgbm` без `FORMULAIC_MODEL_PATH` працює
на `HeuristicDirectionClassifier` (`signal_strategy.py::_build_classifier`), а не на LightGBM.

## 12. Що з джерела НЕ вдалося перевірити

Твердження статті, які **не підтверджуються жодним рядком коду цього репо**.

1. **Sharpe 2.47, прибуток 26.4%, просадка 16.8%** для RL-агента (DQN/PPO/A2C) на погодинному BTC 2018–2022.
2. **+133.52% і Sharpe 1.5029** для найкращої MAS-конфігурації за 52 тижні 2025 року; падіння на **42.57 п.п.** при вилученні Crypto Agent.
3. **F1 0.882** у FinGPT v3.3 проти **0.833** у GPT-4; донавчання на RTX 3090 за **17.25 годин** і **~$17**; BloombergGPT — **$2.67–5 млн** і **1.3 млн GPU-годин**.
4. **Ануалізований прибуток 44.55% і Sharpe 1.55** для long-short портфеля з DSL-рецептів (OOS 2024–2026, витрати 5 б.п.).
5. **IC 0.1501 і просадка 7.98%** у QuantaAlpha: IC у репо рахується, але жодного числа для рецептів не опубліковано, і планку buy&hold не подолав жоден робот.
6. **Ануалізований Sharpe 5.60** у AlgoEvolve.
7. **Прибутковість монолітних LLM на ETH**: Bollinger 2.59% / GPT-3.5 12.35% / GPT-4 22.68% / GPT-4o 21.90% / o1-mini 16.59% — прогону LLM як стратегії в репо немає, тож «парадокс потужності моделей» перевірити нічим.
8. **+7% (BTC), +2% (ETH), >10% (SOL)** від FS-ReasoningAgent і залежність суб'єктивної гілки від бичачого режиму.
9. **Точність >98.50% (рівень 1), 95.00% (рівень 2), Top-3 72.43% (рівень 3)** в аналізі транзакційних графів — ончейн-даних у репо немає.
10. **Падіння Sharpe 51–62% і прибутку 50–72%** у таблиці decay rate (FinMem, FinCON, TradingAgents, QuantAgent) — жодного з цих агентів не запускали.
11. **>85% правильних відповідей про історичні рухи** (FinLake-Bench) і **50 експертних питань щомісяця** (CryptoBench) — зовнішні бенчмарки без відповідника в лабораторії.
12. **OOS-прибуток +31.91% і Sharpe +22.74%** від FactFin; ефективність TimeSPEC і Shapley-DCLR як метрик. Контрфактичний блок у репо є, але MCTS/UCB-пошуку, RAG-векторизації новин і самої метрики витоку немає.
13. **«Просідання стратегії 94.78% за 90 днів»** у Pathia-Trader і твердження, що детермінований DSL Engine його «ізолює»: храповик у репо реалізовано, але цей результат не відтворювався.
14. **Тези про «експоненційно вищу надійність» багатоагентності** й «зменшення витрат на порядки» через FinGPT/LoRA: ні MAS, ні донавчання в репо немає, тому перевірити неможливо в принципі.

Окремо — про власну документацію: у [13 §6](13-ai-2026-vidpovidnist.md) написано, що
`in_sample_score()` ігнорує оборот. Це вже не так — `application/score.py::in_sample_score()` віднімає
`DEFAULT_TURNOVER_HAIRCUT = 0.0005` від `ending_balance`, тобто вибір конфігурації частково cost-aware
(комісії в балансі вже враховані, тому `fees_paid` не віднімається вдруге).
